# YEAR SCORE — 디자인 시스템

> 버전 **1.1** · 2026년 10월 21일(수요일)  
> 적용 대상: YEAR SCORE의 모바일 웹·앱, 태블릿, PC 웹 UI  
> 목적: 새로운 화면도 동일한 미적 기준과 사용성을 갖추도록 하는 **프론트엔드 디자인 기준 문서**  
> **주의:** 이 문서는 디자인 및 화면 문구의 기준이다. 기존 Supabase Auth, 회원 UID, DB, RLS, Storage, API, 미사·악보 데이터의 변경·삭제를 허가하지 않는다.

## 0. 가장 중요한 방향

**Clean · Precise · Contemporary · Professional.** 전례음악가가 사용하는 전문 도구답게 절제되고 정돈된 인상을 만든다. Black & White 기반으로 시각적 소음을 최소화한다.

1. **기능은 보존하고 겉모습만 정리한다.** 기존 백엔드 연결, 인증, 저장·검색·연주 기록을 훼손하지 않는다.
2. **큰 화면 바깥 여백 + 얇고 치밀한 내부 목록.** 카드 외부에는 충분한 공간을, 음악 행에는 불필요한 여백을 두지 않는다.
3. **정확한 열 정렬.** 번호·역할·작품명·작곡가·액션은 같은 열에서 시작한다. 좁은 화면에서도 흔들리지 않는다.
4. **앱 사용의 중심은 전례력이다.** 첫 화면 상단의 큰 Liturgical Calendar 카드가 Home의 정체성을 만든다.
5. **영어 UI + 라틴어 전례음악 항목 + 한국어 날짜 + 영어 전례력 큰 제목.** 작품명과 작곡가명은 정확한 원어 표기를 보존한다. 전례색 약칭(녹·백·자·홍)은 한국어로 둔다. 세부 기준은 PRD의 `Language & Terminology Policy`(P0)를 따른다.
6. **빠른 조작.** Home에서 악보 추가는 최대 2회 조작으로 접근한다. Mass/악보에서 연주 모드는 눈에 띄는 주요 동작이다.
7. **전례 정보는 공식 출처에서.** 목업의 가상 데이터와 미검증 전례일을 실제 서비스 데이터로 넣지 않는다.

### 확정값과 조정값

- **확정 방향:** Black & White, 대표색 `#0B0B0D`, 기본 글자색 Graphite `#3F4450`, 흰 배경 `#FFFFFF`, Pretendard, 좌우 정확한 정렬, Home 구성, 언어 표시 원칙.
- **기본 구현 수치(시안 확정 후 조정 가능):** 여백·행 높이·반응형 너비·제목 크기 등 아래 px 값. 기능 변경을 동반하지 않는 범위에서 실제 기기 테스트로 미세 조정할 수 있다.
- **이전의 초록/청록/브론즈/실버/코발트 브랜드 팔레트 제안은 폐기.** 전례색만 별도 의미색으로 유지한다.

## 1. 컬러 · Color tokens

| 토큰 | 코드 | 용도 |
|---|---|---|
| `--oa-black` | `#0B0B0D` | 브랜드 대표색, 중요한 CTA, 활성 상태, 강조 제목 |
| `--oa-text` | `#3F4450` | 기본 본문, 작품명, 입력 내용 |
| `--oa-muted` | `#858B94` | 작곡가의 보조 줄, 설명, 비활성 보조 텍스트(가독성 확인) |
| `--oa-white` | `#FFFFFF` | 기본 배경·카드 배경 |
| `--oa-line` | `#E9EAEC` | 카드 테두리·목록 구분선 1px |
| `--oa-subtle` | `#F8F9FA` | 꼭 필요한 경우의 희미한 선택·보조 바탕 |
| `--oa-focus` | `#3F4450` | 포커스 표시의 어두운 외곽선 |

- 전체 배경은 **화이트**. 블랙을 큰 패널 전체에 남용하지 않는다. 그라데이션, 텍스처, 두꺼운 그림자, 장식적 컬러 블록은 기본 금지.
- 카드 기본 그림자 **없음**. 카드 경계는 `1px solid #E9EAEC`.
- 주요 화면에서 블랙 배경으로 강조하는 버튼은 가급적 **한 개**. 보조 동작은 흰색·얇은 테두리.
- **전례색은 브랜드 컬러와 독립적 데이터.** 녹·백·자·홍·장미(분홍) 등은 공식 색상에 맞게 작은 점과 글자 이름으로 함께 표시. 백색 점에는 경계선을 적용. 전례색을 버튼 선택 색과 혼동하지 않는다.
- `#858B94` 같은 옅은 글씨는 대형/보조 안내 용도 위주로 쓰고, 작은 필수 안내·입력 라벨·상호작용 요소는 WCAG 대비 기준을 충족하는 더 진한 색을 사용한다.

## 2. 글꼴과 문자 · Typography

**기본:** `Pretendard, -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif`.

| 용도 | 글자 크기 | 줄 높이 | 굵기 |
|---|---:|---:|---:|
| 날짜·페이지 주요 제목 | 24px | 32px | 600 |
| Mass 이름 | 21px | 29px | 600 |
| 주요 섹션 제목 | 17px | 24px | 600 |
| 일반 본문·버튼·곡명 | 14px | 20~22px | 400~500 |
| 음악 목록의 역할 | 13px | 18px | 500 |
| 작곡가·작은 설명 | 12px | 18px | 400 |
| 선택적으로 펼치는 파일 세부정보 | 11~12px | 16px | 400 |

- 기본 자간 `-0.015em`. **영어 제목·작곡가·작품명의 원어 표기는 과도하게 좁히지 않고**, 필요하면 개별적으로 `normal` 적용. 브랜드 워드마크만 예외적으로 넓은 자간 가능.
- 본문 굵기 400·500·600 중심. 너무 많은 크기와 굵기를 만들지 않는다.
- 숫자·시간·번호에는 `font-variant-numeric: tabular-nums`.
- 나란한 두 열의 시작 x좌표는 모든 행에서 정확히 같아야 한다.
- 사용자별 폰트 변경은 후속 기능. 초기 기본은 Pretendard 고정.

## 3. 간격·크기 · Spacing & sizing

| 위치/구성 요소 | 기준 |
|---|---:|
| 모바일 본문 좌우 패딩 | **각 24px** |
| 상단 앱바 아래 첫 콘텐츠까지 | **40px** |
| 마지막 콘텐츠와 하단 내비게이션 사이 | **40px** |
| 주요 섹션/카드 사이 | **24px** |
| 일반 카드 내부 | **20px** |
| 카드 제목과 본문 | **12px** |
| 목록 행 내부 좌우 | **12~16px** |
| Mass 음악 행·Layout 음악 행 | **최소 48px / 공통 기준** |
| 메인/보조 버튼 높이 | **48px** |
| 폼 입력창 높이 | **48px** |
| 태그/칩 높이 | **24px** |
| 아이콘 크기 | **20px**, 작은 아이콘 16px |
| 아이콘 선 두께 | **1.75px** |
| 카드 둥근 모서리 | **12px** |
| 버튼/입력창 모서리 | **8px** |
| 목록 구분선·카드 테두리 | **1px** |

- **40px은 앱바/하단 탭을 제외한 콘텐츠 구간의 여백.** 실제 iOS/Android 상태바와 하단 Safe Area에 중복으로 더하지 않는다.
- **목록 행 48px은 목표 최소 높이.** 원어 제목이 길거나 접근성 폰트 크기가 커지면 54px 이상으로 자연스럽게 확장한다. 48px을 지키려고 글자를 잘라 필수 정보를 잃지 않는다.
- 홈 달력과 화면 섹션은 넉넉하게, 음악 목록·파일 세부정보는 촘촘하게. **모든 요소의 패딩을 일괄 확대하는 것은 금지.**
- 터치 영역은 최소 **44 × 44px**을 확보한다(아이콘 그래픽은 16~20px이어도 클릭 영역을 넓힌다).

## 4. 모바일·태블릿·데스크톱

| 화면 | 범위(기본 제안) | 구조 |
|---|---|---|
| 모바일 | 0~767px | 단일 열, 상단 앱바 + 스크롤 콘텐츠 + 하단 탭, 우선 작업 단순화 |
| 태블릿 | 768~1199px | 상황에 따라 1~2열, 연주 중에는 악보 전체 화면 우선 |
| PC | 1200px 이상 | 왼쪽 메뉴(224px), 중앙 작업 공간, 필요할 때만 오른쪽 상세 패널(300~340px) |

- PC 본문 전체 최대 너비 기준: **1280px**. 지나치게 넓은 텍스트 줄을 만들지 않는다.
- 모바일의 24px 좌우 여백은 유지하되 실제 화면 너비 320px 등의 초소형 단말에서는 레이아웃을 깨뜨리는 대신 유연하게 줄일 수 있다.
- 하단 탭 본체 높이 **64px + 기기 Safe Area**. 실제 기기 상태바를 가짜로 그리지 않는다(독립 시안의 목업 프레임과 실제 앱은 구분).
- 태블릿 **연주 모드**에서는 일반 화면의 24/40px 마진을 그대로 적용하지 않는다. 악보를 최대한 크게 보여주고 넘김 신호의 안정성을 우선한다.

## 5. 공통 구성요소 · Components

### Button

- **Primary:** 높이 48px, 배경 `#0B0B0D`, 글씨 `#FFFFFF`, radius 8px. 한 구역의 최우선 행동에만.
- **Secondary:** 높이 48px, 흰 배경, 1px `#E9EAEC`, 본문 `#3F4450`, radius 8px.
- 기본 로딩·비활성·완료·오류·포커스 상태를 구현한다.
- 고급 그라데이션, 과한 호버 확대/그림자 금지.

### Input / Select / Search

- 48px 높이, 좌우 14px 패딩, 1px 테두리, radius 8px.
- 라벨은 입력 위에, 라벨/값의 시작선을 맞춤. 비어 있으면 placeholder가 실제 값처럼 보이지 않게 한다.
- 작곡가·곡명·교구·성당의 초성/원어 별칭 자동완성은 기존 검색·DB 기능을 재사용한다. **디자인 수정 중 데이터 로직을 새로 만들지 않는다.**
- 검색 중·검색 결과 없음·선택 완료·오류 상태를 제공한다.

### Card / List / Table

- 카드: 흰 바탕, 1px 테두리, radius 12px, 기본 그림자 없음.
- Mass와 Layout의 음악 행은 **같은 48px 최소 높이**, 같은 수직 정렬과 동일한 열 규칙.
- 음악 목록 열: `번호(28px) | 라틴어 역할(약 72~84px) | 작품명·작곡가(유동) | 메뉴(터치영역 44px)`.
- 긴 라틴어 명칭은 Mass 목록에서 승인된 **짧은 표시명** 사용, Layout에서는 전체 표기 확인·편집 가능. 내부 고유 ID/전례 순서는 불변.
- 행 간 간격을 크게 띄우지 않고 1px 구분선. 번호 원형 회색 배지는 최소화하거나 작고 옅게.
- 작품명 14px, 작곡가 12px의 두 줄. 폭이 좁을 때 긴 작품명은 줄바꿈/ellipsis + 접근 가능한 전체 텍스트 제공.
- 같은 자리에서 번호·역할·곡명·메뉴 열의 시작 위치가 변하지 않아야 한다. `justify-between`으로 각 행의 간격을 임의로 벌리지 않는다.

### File details

- `File Details`는 기본 **접힘**. 사용자가 누를 때만 `Created`, `Last updated`, 파일 형식·페이지 수 표시.
- 작은 글씨 11~12px, 행 간격 1~2px, 내용 길이에 맞는 최소 너비(`fit-content`), 라벨 바로 옆에 값 배치.
- 원본 `created_at`은 처음 저장 시각 유지, `updated_at`은 실제 편집 성공을 기준으로 표시(실제 데이터 규칙은 database.md 참조).

### Navigation / Modal / State

- 하단 기본 탐색: **Calendar / Repertoire / Search / Mass** (현재 앱 내 실제 라우트는 조사 후 연결; 이름만 맞추려 라우트를 새로 만들지 않음).
- 주요 헤더는 단정하게, 화면별 제목 위치를 통일. 불필요한 부가 탭 추가 금지.
- 모달은 모바일 스크롤을 하나의 주 스크롤로 정리하고 저장 버튼을 손쉽게 접근하도록 한다.
- 로딩·빈 상태·실패·업로드 진행 중·연결 끊김 등을 사용자에게 명확하게 표시. `null`, `undefined`, API 키, 개발용 임시 문구 노출 금지.

## 6. 화면별 고정 구조 · Screen specification

### A. Home — 앱의 중심은 전례력

**최종 승인된 Home 시안의 정보 구조를 우선한다. Mass 상세 화면처럼 보이지 않아야 한다.**

1. 상단 `YEAR SCORE` 워드마크, 필요한 최소 메뉴.
2. 간결한 Welcome 제목/서브 문구(영어).
3. **한 개의 큰 `Liturgical Calendar` 카드**: 월 이동, 날짜 그리드, 전례색 점, 선택 날짜, `View Full Calendar`.
4. **같은 캘린더 카드 안의 `TODAY` 영역**: 날짜와 공식 전례력의 큰 한글 제목, 전례색 원과 짧은 글자 약칭. 해당 날짜의 Mass로 이동하는 링크.
5. **Quick Actions** 제목 아래 **큰 박스 정확히 두 개**: `Add Score`, `Search`.
6. 하단 내비게이션.

**홈에서 빼야 할 요소:** `Recently Used`, 별도의 Mass 카드, `New Mass`/`Open Repertoire` Quick Actions 카드, 여러 개의 작은 대시보드 패널. Home에는 새 기능을 이유로 카드를 임의 추가하지 않는다.

- 달력의 점은 **공식 전례색**과 **사용자 일정 존재 표식**을 개념적으로 구분한다. 검증되지 않은 전례색을 날짜에 채우지 않는다.
- 날짜를 누르면 그 날짜의 Mass/저장 공간으로 연결한다. 오늘 날짜와 현재 선택 날짜가 다르면 라벨·조회 데이터를 혼동하지 않는다.
- `Readings / Proper` 등 보조 정보로 가는 작은 링크는 기존 승인된 달력 카드 안에서만 다루고, 별도 대형 섹션으로 만들지 않는다.
- **Add Score는 첫 화면에서 최대 2회 동작으로 촬영·업로드 위치에 접근**해야 한다.

### B. Mass — 실제 준비와 연주

1. 상단 제목 `Missa`.
2. 큰 날짜는 한국어, 전례 명칭(전례 시기·전례주년·전례일·대축일·축일)은 영어(출처 순서는 §7 표). 공식 전례 정보는 해당 날짜 기준으로 정확하게 표시.
3. Missa 카드: 영어 미사 종류/시간/장소/Music Parts, 한 개의 핵심 검정 CTA `Open Performance Mode`, 보조 `Add Score`.
4. 음악 목록의 제목은 **`Music`**. 음악 항목 역할은 **라틴어**, 작품 제목·작곡가는 원어.
5. 48px 최소 높이의 정확하게 정렬된 음악 목록. 순서 번호·역할·작품·작곡가·메뉴.
6. 불필요한 파일 저장·수정 메타정보는 기본 접음.

- 사용자가 작성한 고유 Mass 이름/장소는 **그대로 보존**한다. `11시 교중미사`처럼 기존에 한글로 저장된 이름을 자동으로 영어 번역하거나 DB 값을 덮어쓰지 않는다. 예시 UI와 신규 기본 표시명만 영어 우선.
- 미사와 악보의 연결 상태, 순서, 기록은 기존 DB에서 로드한다. 목업의 가짜 작품명·연주 기록 사용 금지.

### C. Layout — 음악 부분만 사용자 설정

1. 헤더 `Music Parts`, 제목 `Your Music Parts`. 내부 주소 `#/layouts`와 DB 표 이름은 그대로 둔다.
2. 저장한 선택(`Saved Parts`) 이름 입력·선택.
3. 목록 제목은 **`Music Parts`**. 음악 역할은 라틴어만 표시하고, 한국어·영어 명칭은 검색용으로 보관한다.
4. 음악 항목 행은 Mass와 동일한 48px 기준·정렬·구분선.
5. 사용자가 포함 여부·표시 명칭·연결 악보를 편집하지만 **공식 미사 전례 순서와 고유 식별자는 수정 불가**.
6. `Save Selection`은 검정색 주요 버튼.

- 기본 라틴어 명칭은 전례서/운영자 검증 자료를 따른다. 사용자 정의 음악 슬롯은 공식 전례 요소인 것처럼 표시하지 않는다.
- 기존 Layout 및 그날의 연결 악보가 편집 UI 변경 때문에 삭제되거나 중복 생성되지 않아야 한다.

## 7. 표기 언어 · Content & localization

| 콘텐츠 | 기본 표시 원칙 |
|---|---|
| 날짜 | **한국어**, 예: `2026년 10월 21일(수요일)` |
| 전례 명칭 (전례 시기·전례주년·전례일·대축일·축일·신심/기원 미사) | **영어**. ① 한국 교회 매일미사 영어 제목(굿뉴스 매일미사 목록의 영어 표기) ② 그 표기가 미국 전례력을 따라 한국 전례일과 다르거나 없으면 로마 미사 경본 영어판(USCCB) 표기 ③ 둘 다 확인되지 않으면 기존 한국어 명칭을 그대로 표시. 영어를 임의로 만들지 않는다 |
| 전례색 약칭 | **한국어** (`녹`, `백`, `자`, `홍`, `장미`) |
| 메뉴·버튼·보조 안내 | **영어** (`Add Score`, `Search`, `Music Parts`, `Save Selection`) |
| 미사 명칭 | **라틴어** `Missa`(복수 `Missae`), 예: `+ Add Missa`. DB·주소의 `mass` 이름은 바꾸지 않는다 |
| 미사 음악 목록 제목 | **영어** `Music` |
| 음악 항목 | **라틴어** (`Praeludium`, `Introitus`, `Kyrie`, `Communio` 등). 확인되지 않은 라틴어는 만들지 않는다 |
| 작품명 | **작품의 실제 원어/관례적인 원제목** (작곡가 국적에 맞춰 임의 번역하지 않음) |
| 작곡가명 | **음악학적으로 확인된 원어 표기·정식 철자·발음기호/악센트 보존** |
| 사용자 작성 미사명·성당명·메모 | **원문 보존**. 한국어로 작성되었다고 강제 번역 금지 |
| 개인별 언어 선택 | 추후 `ko`·`en` 전환 가능하게 구조 유지, 지금은 승인된 혼합 표기 적용 |

- 전례력과 공식 가톨릭 용어는 미확인 라틴어로 억지 번역하지 않는다.
- 영어 전례 명칭은 운영자 기준 표 `liturgical_observances.name_en`에 둔다. Missa 기록의 `celebration_name`(저장 당시 복사한 한국어 명칭)은 바꾸지 않고, 화면에서 연결된 전례일(`observance_id`)의 영어 명칭을 보여준다. 사용자가 직접 입력한 전례 이름은 입력한 그대로 표시한다.
- 전례 시기·색·거행 명칭은 검증된 자료를 사용한다. **2026년 10월 21일(수요일)은 `연중 제29주간 수요일`이며 목업의 `연중 제30주일` 표기는 사실 확인이 된 데이터가 아니므로 복사하지 않는다.**
- UI 문구는 가능하면 번역 키/상수로 중앙 관리하여 향후 언어 전환을 쉽게 한다.

## 8. 접근성·행동 규칙

- 본문 및 컨트롤 대비 최소 **4.5:1** 목표; 큰 글씨는 **3:1**. 포커스 표시는 선명하고 키보드로 이동 가능.
- 상호작용 요소 터치 범위 최소 **44×44px**. 48px 목록 행의 메뉴 아이콘은 별도의 접근 가능한 라벨과 터치 범위를 확보.
- 클릭/터치 피드백: **100~150ms 목표**, 일반 전환 애니메이션 **150ms**. 진행 상황과 에러는 즉시 표시.
- 사용자가 `prefers-reduced-motion`을 설정하면 애니메이션을 줄인다.
- 검색·악보 저장·미사 링크·연주 모드처럼 기능적으로 중요한 행동을 장식적인 애니메이션으로 지연시키지 않는다.
- 연주 모드의 실제 태블릿/페달 동작은 이 UI 스타일과 별도 테스트(안정성과 악보 가독성 우선).

## 10. Cursor 적용 절차 — 반드시 작은 범위부터

1. **읽기 전용 분석:** `PRD.md`, `docs/database.md`, 본 파일, 현재 화면·공통 컴포넌트·글꼴·CSS/Tailwind 구조 확인. 기존 코드와 충돌·작업 파일·위험 보고.
2. **토큰 및 공통 요소:** 컬러·글꼴·간격·버튼·입력·카드·목록 규칙을 기존 스타일 체계에 매핑. 실제 DB에는 접근하지 않는다.
3. **Home부터:** 최신 승인 구조인 **큰 Calendar 카드 + TODAY + Add Score/Search 두 박스만** 적용하고 기존 API를 연결한다. 사용자에게 실제 화면을 보여주고 승인받는다.
4. **Mass와 Layout:** 동일 토큰을 적용하고 **음악 행 최소 높이 48px**을 공통으로 검증. 한국어 날짜, 영어 전례 명칭(출처가 확인되기 전에는 한국어), 라틴어 음악 항목, 나머지 영어 표기 점검.
5. **나머지 화면 확장:** Repertoire, Search, Score Library 등에 단계적으로 적용. 하나의 전역 CSS 수정으로 기존 화면이 깨지지 않도록 회귀 테스트.
6. **테스트:** 모바일 375/390/430px, 태블릿 768px, 데스크톱 1440px에서 스크롤·정렬·버튼·포커스 검사. 로그인, 달력 조회, 악보 업로드, 연결·재사용, 기존 검색·연주 진입 확인.

**DB 변경이나 마이그레이션이 필요하다고 판단되면 이유와 구체적인 SQL을 먼저 보여주고 승인을 기다린다. 디자인 작업을 이유로 기존 데이터를 수정하거나 지우지 않는다.**

## 11. 완료 기준 · Acceptance criteria

- [ ] 모든 대표 화면은 Black & White + Pretendard 디자인 토큰을 공유한다.
- [ ] 첫 Home에는 큰 Liturgical Calendar 카드 및 TODAY가 있고 Quick Actions는 Add Score·Search 두 개뿐이다.
- [ ] 상하 콘텐츠 간격 40px, 좌우 24px이 유지되며 iOS/Android Safe Area와 겹치지 않는다.
- [ ] Mass와 Layout 음악 행의 최소 높이는 48px이고 열 정렬이 정확하다.
- [ ] 라틴어 역할명, 영어 UI, 한국어 날짜, 영어 전례력 제목, 작품·작곡가의 원어 표기가 구분된다.
- [ ] 목업의 가상 전례력·미사·작품명이 운영 데이터로 유입되지 않는다.
