# YEAR SCORE — 제품 요구사항 정의서 (PRD)

- **버전:** 0.4 (통합 검색·연주 횟수·악보 재사용 반영)
- **상태:** 개발 설계 초안 · 기능 요구사항, 구현 여부 미검증
- **서비스명:** YEAR SCORE (가칭)
- **제품 유형:** 가톨릭 전례음악 전문 웹 애플리케이션
- **개발 원칙:** 기존 회원가입·로그인 기능과 사용자 UID를 보존하고, 나머지 백엔드를 검증 후 단계적으로 재설계한다.

> **문서 사용 주의:** 이 문서는 제품 요구사항이다. 현재 코드·DB의 구현 상태를 보증하지 않는다. 인증·운영 DB·파일을 삭제하거나 마이그레이션하기 전에 백업과 영향 분석 및 사용자 승인을 거친다.

## 1. 제품 비전 (Product Vision)

YEAR SCORE는 가톨릭 오르가니스트, 미사 반주자, 성가대(합창단) 지휘자 및 음악가를 위한 전문 전례음악 관리 플랫폼이다. 전례력 확인 → 성가 선곡 → 미사 준비 → 악보 관리 → 연습 → 실제 연주 → 기록 보존을 하나의 흐름으로 연결한다. 단순 파일 저장소가 아닌 **전례음악가의 전문성과 음악적 경험이 지속적으로 축적되는 작업 공간**을 지향한다.

**슬로건:** *Prepare. Practice. Perform. It stays with you.*  
**한국어:** 준비하고, 연습하고, 연주하는 그 모든 과정이 당신의 기록으로 남습니다.

## 2. 주요 사용자 (Target Users)

- 가톨릭 오르가니스트 및 미사 반주를 담당하는 음악가
- 성가대(합창단) 지휘자
- 가톨릭 전례음악가 및 음악 담당자
- 전례음악 연구자·학습자
- 미사 반주를 처음 시작하거나 경험이 적은 사용자

**명칭 결정 보류:** 국내에서 ‘오르가니스트’와 ‘미사 반주자’가 주는 전문성·인상 차이를 검토해 실제 서비스의 사용자 호칭을 추후 확정한다. 이 문서의 명칭은 대상 범위를 설명하기 위한 임시 표현이다.

**숙련도별 정보 제공:** 초보 사용자를 위해 미사 반주 입문 정보, 전례 시기별 주의사항과 기본 안내를 제공하되, 전문가에게 안내를 강제하지 않는다. 안내는 표시/숨김할 수 있어야 하며, 전례적 규범과 조언·개인 해설을 구별하고 출처를 표시한다.

## 3. 제품 설계 원칙 (Product Principles)

1. **정확성:** 전례 및 음악학 자료의 출처·검증 상태·불확실성을 기록한다.
2. **전문성 존중:** 불필요한 안내를 강제하지 않는다.
3. **개인화:** 정보의 표시 여부, 순서, 저장된 보기 구성을 사용자가 제어한다.
4. **기록의 지속성:** 미사·연주·선곡 기록은 검색 및 재사용할 수 있다.
5. **연주 안정성:** 실제 미사에서 빠른 페이지 이동·사전 준비·오프라인 열람을 우선한다.
6. **저작권 보호:** 복음 본문·전례문·악보의 이용권을 관리한다.
7. **데이터 독립성:** 공통 기준 데이터와 사용자 개인 기록·파일을 분리한다.
8. **검색 중심 설계:** 작품·전례·연주 역할·개인 사용 이력의 교집합(AND) 검색을 제품의 최우선 핵심 기능으로 설계한다.
9. **악보의 지속적 재사용:** 한 번 저장한 악보는 재업로드 없이 여러 미사·템플릿·연습·아카이브에 연결한다.
10. **비파괴적 편집:** 악보 원본과 기존 기록을 보호하고 수정 이력을 남길 수 있도록 한다.

## 4. 핵심 기능 (Core Features)

### 4.1 가톨릭 전례력 (Liturgical Calendar)

운영자가 검증한 날짜별 가톨릭 전례력을 제공한다.

**기본 데이터:** 날짜, 전례일 명칭, 전례 시기(대림·성탄·연중·사순·부활), 전례색, 복음 환호송 및 고유 구절, 복음 성경 참조, 허가된 경우 복음 본문, 출처·검증 상태. 제1·제2독서 참조는 4.2의 독서 정보로 지원한다.

**날짜 표기 필수 형식:** `2026년 10월 25일(일요일)`처럼 **연·월·일·요일을 모두 명확히 표시**한다. 전례일 예시: `연중 제30주일 (녹) ●`.

전례색은 `(녹)`, `(백)`, `(자)`, `(홍)`, `(분홍)` 등의 약어와 대응 색상으로 전례일 옆에 표시한다. 별도 전례색 설명 영역은 기본 화면에 두지 않는다. 전례일 명칭·색상은 항상 보이며, 색은 시기만으로 추론하지 않고 날짜별 검증 데이터에 따른다. 예외 색상도 확장 가능하게 설계한다.

### 4.2 독서·복음 본문과 저작권 (Readings, Gospel and Copyright)

복음 본문을 가능하면 앱 안에서 열람하게 하는 것이 목표다. **1단계**에서는 제1독서·제2독서(해당 시)·복음 참조와 복음 환호송 참조를 보여주고 적법한 공식 출처로 연결한다. **2단계**에서는 이용 허락을 확보한 번역·본문만 앱 내 표시한다. 권리자·번역·출처·이용 범위·저작권 표시·캐싱/저장/배포 조건을 기록한다. 공개 웹페이지에 있다는 이유만으로 전문을 복제·스크래핑·임베딩하지 않는다.

### 4.3 운영자 전례력 관리 (Admin Liturgical Calendar)

운영자는 공통 기준 데이터를 생성·수정·검증·공개하고 출처·권한·수정 이력을 관리한다. 관리자 편집 화면의 필드 표시, 순서, 그룹, 안내 문구를 편집할 수 있다. 사용자 정의 필드는 미래 확장 대상으로 한다. 일반 사용자는 공통 전례력을 수정하지 않는다.

### 4.4 지역별·특별 미사 (Special Liturgical Mass)

지역별·성당 고유 전례, 장례·혼인 등 특별 미사/예식의 정보를 개별 미사에 추가·선택할 수 있다. 공통 전례력은 덮어쓰지 않으며, 실제 허용되는 전례일과 독서 선택은 전례 규정에 따라 확인한다.

### 4.5 개인화된 전례력 보기 (Personalized Calendar Views)

사용자는 전례 시기·독서·복음 환호송·복음 참조·본문 열기·선택 항목을 표시/숨김하고 순서를 저장한다. `최소 / 기본 / 상세 / 사용자 지정` 보기와 여러 개의 저장된 보기 구성을 지원한다. 기본 구성은 운영자가 정한다. **전례일 명칭·전례색은 숨길 수 없다.** 표시 설정은 데이터를 삭제하지 않는다. 초보 사용자 설명도 선택적으로 표시한다.

### 4.6 미사 일정 (Mass Event Management)

미사 생성·조회·수정·삭제(CRUD)를 지원한다. **같은 날짜에 최소 두 개, 가능하면 개수 제한 없이 독립적인 미사**를 저장한다. 각 미사는 날짜·시간·성당/장소·전례 정보·특별 미사 설정·성가 및 연주곡 순서·악보·개인 메모·적용 템플릿을 개별 보유한다.

**템플릿에서 악보까지의 탐색 요구사항(중요):** 미사 또는 적용된 템플릿을 누르면 **순서대로 정렬된 목차**가 즉시 나타난다. 목차의 곡을 누르면 그 곡에 연결된 악보가 열려야 한다. 악보의 마지막 페이지까지 연속 이동할 수 있어야 하고, 다음 페이지와 다음 곡의 악보로 자연스럽게 전환되어야 한다. 목차·악보 화면에서 **연주 모드로 즉시 전환**할 수 있어야 한다. 곡에 악보가 없는 경우 명확히 표시한다.

### 4.7 반복 미사 템플릿 (Recurring Mass Templates)

매주, 매월 첫째·셋째 주일, 둘째·넷째 주일, 선택 주차/날짜 반복을 지원한다. 템플릿의 곡 순서·연결 악보를 재사용하며, 적용할 때 기존 미사 기록은 덮어쓰지 않는다. **템플릿 사용 횟수**를 기록한다(기존 요구사항 유지).

### 4.8 음악학적 작품 데이터베이스 (Musicological Work Database)

**작품 정보와 악보 파일은 별도 개체로 관리한다.** 작품 메타데이터: 원어 제목과 번역 제목, 작품번호, 작곡가, 생몰년·국적, 작곡연도/추정 시기, 음악사적 시대, 역사·문화적 배경, 형식·양식, 조성, 예상 연주 시간, 의도된 악기(근거 있는 경우), 역사적으로 연관된 오르간, 실제 연주 악기, 학술 자료, 참고문헌, 정보 확실성 수준.

**제목 표기:** 원어 제목을 보존한다. 독일어권 작품은 독일어, 프랑스어권 작품은 프랑스어 등 실제 원어를 우선한다. 영어 제목은 기본 보조 표기로 제공할 수 있으나 원어를 임의로 영어로 대체하지 않는다.

**작곡가 표기:** 목록에는 `J. S. Bach`처럼 약칭을 쓸 수 있다. **마우스 호버 및 터치 기기에서 길게 누르기/정보 버튼**으로 풀네임, 생몰년, 국적을 확인하게 한다. 터치·키보드 접근성을 위한 별도 열기 방식도 제공한다. 작곡가의 국적 표기에는 역사적 맥락과 확실성도 고려한다.

사용자는 작품 화면에 보일 메타데이터 항목과 순서를 선택하여 개인 설정으로 저장할 수 있다. 미확인 학술 정보는 사실로 단정하지 않는다. 공통 작품 데이터와 개인 악보·메모를 분리한다.

### 4.9 악보 라이브러리 (Score Library)

PDF·JPG·PNG 등을 업로드하고 작품·판본·편집자 정보에 연결한다. 사용자 악보 파일은 기본 비공개이며 공유/배포는 권한을 확인한다. 동일 작품에 복수 판본을 연결하고, 기존 악보를 수정·버전 관리할 수 있게 한다.

**한 번 저장한 악보의 무제한 재연결(필수):** 동일 사용자가 보유한 하나의 악보를 다음 주일 미사, 평일 미사, 특별 미사, 다른 날짜의 미사, 여러 템플릿, 연습용 목록 및 과거 연주 기록에 **언제든 다시 연결**할 수 있어야 한다. 재연결 시 PDF를 다시 업로드하거나 같은 파일을 중복 저장하도록 요구하지 않는다. 검색 결과·악보 라이브러리·미사 목차에서 기존 악보를 선택해 연결한다. 각 연결에서 선택한 곡 순서·전례 역할·개인 메모는 개별적으로 보유한다.

**파일과 연결의 분리:** 악보 파일/악보 리소스에는 변하지 않는 고유 식별자를 부여하고, 미사 또는 템플릿에는 별도의 연결 레코드를 저장한다. 한 곳에서 악보 연결을 해제해도 다른 미사·템플릿·아카이브의 연결이나 실제 저장 파일은 삭제하지 않는다. 원본 악보의 교체·편집이 기존 연결에 미치는 영향(최신판 동기화 또는 특정 버전 고정)을 명확하게 선택·표시한다. 악보 자체 삭제 요청 시에는 다른 연결의 존재와 영향 범위를 먼저 알리고 확인을 받아야 한다.

### 4.10 악보 촬영·보정·PDF 편집 (Score Scanning and Editing)

사진 악보에 대해 문서 모서리 탐지, 원근 보정, 회전·기울기 보정, 밝기·대비·배경 보정, 여러 페이지 PDF 묶기, 미리보기, 수동 재보정을 지원한다. 오선·음표·임시표·덧줄·아티큘레이션 손상을 최소화한다.

**페이지 편집 필수:** 저장 후 페이지 추가·삭제·순서 변경·회전·재촬영 교체가 가능해야 한다. 예를 들어 **10페이지 중 5페이지만 다시 찍어 같은 자리에 교체**하고 나머지 페이지는 유지할 수 있어야 한다. 기존 PDF를 통째로 다시 촬영하도록 요구하지 않는다. 변경 후 PDF를 다시 생성·저장하고 이전 파일을 보호하거나 복원 가능한 버전을 유지한다.

**용량 및 보관 정책 — 설계 제안:**
- 기본 열람본은 악보의 가는 기호가 보존되는 범위에서 효율적인 해상도와 압축 방식으로 PDF 생성. 흑백/회색조를 기본 후보로 두되 사용자에게 컬러 보관 옵션 제공.
- 원본 촬영 이미지는 처음에는 보관하되, 사용자가 **보정본 확인 후 원본 개별 또는 전체 삭제**를 선택할 수 있게 한다. 삭제 시 되돌릴 수 없는 범위와 기존 편집 가능성에 미치는 영향을 명확히 알린다.
- 원본과 보정본의 파일 크기 표시 및 저장 공간 사용량 제공.
- 미리보기·썸네일은 별도 경량 파일로 생성하고, 페이지 단위 편집 정보를 유지해 전체 문서를 불필요하게 재처리하지 않도록 설계.
- 품질 기준과 목표 파일 크기는 다양한 실제 악보(희미한 인쇄·손필기·색상 메모 포함)로 테스트 후 확정한다. 고정 DPI·용량 제한을 검증 없이 확정하지 않는다.

초기 목표는 문서 보정이며 음표 자체를 편집 가능한 데이터로 읽는 OMR은 후순위다.

### 4.11 연습 및 미사 모드 (Rehearsal / Mass Mode)

태블릿에서 미리 정한 곡 순서·목차·악보를 빠르게 오가며 전체 페이지를 열람한다. 이전/다음 페이지, 이전/다음 곡, 확대·축소, 큰 터치 영역, 팝업 최소화, 오프라인 저장·준비 상태, 즉시 연주 모드 전환을 지원한다.

PWA·Service Worker·IndexedDB/로컬 저장·PDF 렌더링 사전 로딩·캐시 적용을 검토한다. 사전 준비된 페이지 이동 **0.2초 이내**를 목표로 삼되 iPad/Android 실기기에서 측정한다. 오프라인 준비 완료 표시 후에는 실제 오프라인에서 모든 연결 악보를 열 수 있어야 한다.

### 4.12 개인 연주 아카이브 (Performance Archive)

날짜·장소·작품·연결 악보·적용 템플릿·개인 메모 기반으로 과거 미사를 검색하고 재사용한다. 미사 일정과 곡별 실제 사용 이력은 작품의 검색·통계에 연결되어야 한다.

**연주 횟수의 신뢰성:** 미사 일정에 곡을 저장한 **배정 횟수**는 확인된 실제 연주 횟수와 구분해 기록한다. 미사를 연주 완료로 표시하거나 실제 연주를 확인한 경우에만 **확인된 연주 횟수**에 반영한다. 과거에 저장된 일정만 있는 경우에는 그 횟수를 필요에 따라 **일정 기반 추정 횟수**로 표시할 수 있으나 확정 실적으로 표현하지 않는다. 취소된 미사는 실제 연주 횟수에서 제외한다. 같은 작품이 한 미사에서 여러 번 사용된 경우에는 사용 항목(연주 발생 건) 단위로 집계하되, 사용자가 미사 횟수와 연주 건수를 혼동하지 않게 한다.

### 4.13 통합 검색 및 다중 조건 교집합 검색 (Integrated & Intersection Search)

**최우선 핵심 기능:** YEAR SCORE 검색은 단순 키워드 검색을 넘어 사용자가 쌓은 미사·선곡·연주 이력을 기반으로 여러 조건을 **동시에 만족하는 결과만** 반환하는 교집합(AND) 검색을 지원해야 한다. 데이터베이스 설계 초기부터 구현하고, MVP에 포함한다.

**1. 검색 대상**

- 작곡가, 곡명, 작품번호, 원어 제목·영어 제목·한국어 제목·번역 제목
- 음악사적 시대(바로크·고전·낭만·현대 등), 형식·양식, 조성
- 전례 시기(대림·성탄·연중·사순·부활), 전례일, 관련 날짜
- 전례 역할(전주·후주·영성체 후 묵상 등): **그 작품이 실제 미사에서 수행한 역할**과 연결
- 성가 제목·성가번호
- 개인 악보 파일, 판본, 보유 여부, 연결된 작품
- 개인 미사 일정에 해당 작품 또는 악보를 **배정한 횟수**
- 개인 아카이브의 **확인된 실제 연주 횟수**, 필요시 **일정 기반 추정 횟수**
- 개인 미사 일정·연주 이력·템플릿의 연관 기록

**2. 다국어·명칭·조성 정규화**

작곡가와 작품은 원어·영어·한국어 명칭, 통용 약칭과 대체 명칭(Alias)으로 검색한다. 작품번호는 정확 일치를 우선하며 띄어쓰기·대소문자·간단한 오탈자 차이에 대응한다. 예: `Bach / 바흐 / J. S. Bach / Johann Sebastian Bach`, `d minor / D minor / dm / 라단조`. 조성 표준값과 검색용 동의어를 구분하고, 작품/편곡/판본에 따른 조성 차이가 존재하면 정확히 구분한다.

**3. 교집합(AND) 검색 — 필수**

여러 조건을 선택하면 동일한 작품과 그에 연결된 사용 기록이 **모든 조건을 만족**해야 한다. 조건별로 무관한 다른 사용 기록들을 조합하여 실제로 없었던 결과를 만들어서는 안 된다.

- 예시 A: `전례 시기 = 성탄` **AND** `연주 횟수 ≤ 2회`
- 예시 B: `전례 역할 = 영성체 후 묵상` **AND** `조성 = d minor(라단조)` **AND** `연주 횟수 ≤ 3회`
- 같은 검색에서 `≤ (이하)`, `≥ (이상)`, `= (정확히)`, `범위(최소~최대)` 조건을 바꿀 수 있어야 한다. `0회(아직 연주하지 않음)`도 검색 가능해야 한다.
- 사용자별 연주 횟수에 대해서는 `전체 기간의 연주 횟수`와 `선택한 전례 시기·역할·기간 안에서의 연주 횟수`를 **명시적으로 구분**하여 선택할 수 있게 한다. 검색 결과에 적용한 집계 범위와 연주 횟수의 종류(배정/확인/추정)를 표시한다.
- 기본 AND 조건은 작품의 공통 메타데이터와 **사용자 본인의 미사 곡 사용 기록**을 기준으로 판정한다. 공통 전체 사용자의 개인 기록을 합산하지 않는다.
- 상세 필터는 작곡가, 자료 종류, 시대, 형식·양식, 조성, 전례 시기, 전례일, 전례 역할, 악보 보유, 연주 이력 유무, 횟수 범위 및 기간을 지원한다.

**4. 검색 결과 표시와 행동**

결과에는 기본적으로 **작품명(작품번호 포함), 작곡가, 자료 유형**을 표시한다. 추가 메타데이터는 사용자별 표시 설정에 따라 선택한다. 검색과 연관된 연주 횟수 및 집계 범위를 확인할 수 있어야 한다. 결과에서 작품의 학술 정보, 보유 악보·판본, 연주·미사 기록으로 이동할 수 있다.

검색 결과에서 작품/기존 악보를 **즉시 미사 일정·미사 템플릿·연습 목록에 연결**할 수 있어야 한다. 이미 보유한 PDF는 재업로드 없이 바로 열람한다. 하나의 악보를 여러 곳에 연결해도 파일은 중복 저장하지 않는다.

**5. 검색 정확성·평가**

작곡가·작품의 고유 ID, 표준 명칭·대체 명칭·작품번호를 관리하여 중복을 줄인다. 이름이 같은 다른 작품을 구별한다. 정확한 작품번호/제목 일치, 관련성 및 지정 필터를 기준으로 결과를 정렬한다. 대표 검색 사례와 예상 결과를 테스트 데이터로 유지하며, 특히 **다중 필터·횟수 경계값(0, 2, 3회)·이하/이상 전환·취소/완료 상태**를 검증한다.

**6. 권한과 성능**

운영자 공통 작품 정보는 허용 범위에서 검색 가능하며, 악보·미사·연주 횟수는 로그인한 사용자가 접근 가능한 기록만 포함한다. Supabase/PostgreSQL의 정규화된 관계형 테이블, 검색 색인, 전문 검색, 별칭 테이블 및 필요 시 `pg_trgm`을 우선 검토한다. 다중 조건의 조인과 횟수 집계는 실제 데이터 규모에서 성능을 검증한다.

**7. 향후 AI 검색**

자연어 질의 및 의미 기반 검색은 향후 확장으로 검토한다. 검증된 메타데이터 검색과 AND 필터·연주 횟수 검색을 AI 기능보다 우선 구현한다. AI 생성·추천 정보는 검증된 사실과 구분한다.

### 4.14 초보자를 위한 선택형 가이드 (Optional Beginner Guidance)

처음 미사 반주를 시작하는 사람을 위해 전례 시기별 기초 주의사항, 미사 중 반주 준비 점검 사항, 기본 용어와 참고 출처를 제공한다. 공식 규정·전례 관행·운영자 조언을 명확히 구분한다. 초보자 보기에서 안내를 기본 노출할 수 있지만 사용자는 숨기거나 전문가용 간결한 보기로 전환할 수 있어야 한다.

## 5. 데이터 및 권한 정책 (Data and Permissions)

**운영자 기준 데이터:** 공식 전례력, 검증된 전례 정보, 공통 작곡가·작품 정보.  
**개인 데이터:** 미사 일정, 미사별 곡 배정·전례 역할·완료 상태, 악보와 보정 원본 및 재사용 연결, 연주 기록·횟수·메모, 저장된 보기 구성, 개인 특별 미사 설정.

기존 Supabase Auth, 사용자 UID, 리디렉션·로그인 설정을 유지하고 RLS로 계정별 접근 권한을 보호한다. 공통 자료를 편집할 수 있는 관리자 권한과 일반 사용자 권한을 분리한다. 개인정보·저작권 자료의 공개/공유는 별도 정책을 따른다.

## 6. MVP 개발 우선순위 (MVP Development Priorities)

1. **보호 및 검증:** 기존 인증 보존, 코드·DB·파일 백업, 실제 구현 상태 확인, DB/RLS 설계.
2. **검색용 데이터 구조와 핵심 미사 관리:** 작품·작곡가 표준 ID·별칭·조성·전례 역할·전례 시기·사용 횟수의 관계형 데이터 설계. 최소 검증된 전례 데이터, 미사 일정·곡별 순서·연주 상태·반복 템플릿·목차와 악보 연결 구현.
3. **핵심 검색 MVP와 악보 재사용:** 작품명·작곡가·작품번호·다국어/별칭·조성 검색, 전례 시기+전례 역할+연주 횟수 **교집합(AND) 필터**, 횟수 이하/이상/범위·집계 범위 선택, 기존 악보의 다중 미사·템플릿 연결, 사용자별 표시 설정 구현. **이 검색은 나중으로 미루지 않는다.**
4. **연주 안정성:** PDF 뷰어, 연속 페이지·다음 곡 이동, 연주 모드, 사전 다운로드·오프라인 사용.
5. **확장:** 촬영 악보 보정·페이지 단위 편집, 관리자 폼 고도화, 선택형 초보자 가이드 확장, AI 정보 추출, 결제·협업.

**의존성 주의:** 촬영 PDF 보정보다 먼저 기본 악보 파일 업로드·열람·페이지 이동 흐름을 검증한다. 다만 촬영 보정은 제품 차별화 기능이므로 지원 기간과 구현 난도에 따라 4단계와 병행하는 별도 작업으로 추진할 수 있다.

## 7. 기능 완료 기준 (Acceptance Criteria)

1. 기존 회원의 로그인·로그아웃·재로그인이 계속 정상 작동한다.
2. 날짜가 항상 `YYYY년 M월 D일(요일)` 형식으로 명료하게 표시된다.
3. 같은 날 복수 미사를 별도로 생성·수정·조회한다.
4. 공통 전례력은 일반 사용자가 변경할 수 없고, 특별 미사는 개별 일정에 연결한다.
5. 전례일과 전례색은 항상 보이고, 기타 전례 정보는 표시/숨김 및 순서 저장이 가능하다.
6. 독서·복음 전문은 적법한 방법으로 열람한다.
7. 미사/템플릿 목차의 곡을 눌러 연결 악보를 열고 마지막 페이지까지 이동하며 다음 곡으로 전환할 수 있다.
8. 목차·악보에서 연주 모드로 즉시 진입한다.
9. 작곡가 약칭에서 풀네임·생몰년·국적을 호버/길게 누르기/정보 버튼으로 볼 수 있다.
10. 작품 정보 표시 항목과 순서를 개인별로 저장한다.
11. 작품 하나에 여러 악보·판본·연주 기록을 연결한다.
12. 촬영 악보를 보정·PDF 저장하고, 저장 후 가운데 페이지만 교체·재정렬·삭제할 수 있다.
13. 촬영 원본과 보정본을 구분하고 원본 삭제 선택권 및 용량 정보를 제공한다.
14. 오프라인 준비 완료한 미사의 악보를 인터넷 없이 열람한다.
15. 초보자 가이드는 선택적으로 켜고 끌 수 있다.
16. 사용자 A는 사용자 B의 비공개 기록·악보에 접근하지 못한다.
17. 새로고침·재로그인 후에도 데이터와 개인 보기 설정이 유지된다.
18. 동일한 악보를 재업로드 없이 서로 다른 두 날짜의 미사, 둘 이상의 템플릿 및 연습 목록에 연결할 수 있다.
19. 한 미사에서 악보 연결을 해제해도 다른 일정·템플릿의 악보 및 저장 파일이 유지된다.
20. `성탄 AND 확인된 연주 횟수 ≤ 2회` 조건 검색이 작동하고 `≥ 2회`로 변경해 다른 결과를 볼 수 있다.
21. `영성체 후 묵상 AND 조성 = d minor AND 확인된 연주 횟수 ≤ 3회` 조건 검색이 작동한다.
22. 필터의 집계 범위(`전체`/`선택 조건 내`)와 횟수 유형(`배정`/`확인`/`추정`)을 사용자가 구별해 선택할 수 있다.
23. 계획만 세운 미사·취소한 미사가 자동으로 확인된 실제 연주 횟수에 포함되지 않는다.
24. 서로 다른 곡 사용 이력의 조건이 잘못 결합되어 허위 교집합 결과가 생성되지 않는다.

- 작곡가 생몰년·국적 표기에서 역사적 예외 처리
- 스캔 이미지 품질 대비 크기, 파일 수명주기와 원본 삭제·버전 정책
- iPad·Android에서 PDF 편집·오프라인 열람 성능
- 관리자 화면 구성 편집의 1차 범위
- 과거 미사 일정의 연주 완료 여부를 확인할 방법과 일정 기반 추정 횟수의 표시 정책
- 연주 횟수를 작품 기준/악보 판본 기준/실제 사용 건수 기준으로 구분하는 UI
- 필터 적용 시 연주 횟수의 기본 집계 범위(전체 기간 또는 선택 조건 내)
- 악보 수정·버전 변경 시 기존 미사/템플릿이 최신판 또는 고정판 중 무엇을 열지에 관한 기본 정책

확인 전에는 구현 완료로 표시하지 않는다.
